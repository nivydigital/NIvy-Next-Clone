# Execution & Verification

## ⚡ QUICK VIEW
- **Purpose:** Record what was executed and prove the result.
- **Start here:** Add one entry for each meaningful work unit.
- **Required evidence:** Action + files + test/inspection + result + commit + next action.
- **Rule:** Created files ≠ completed work.

## Verification Rule
Prefer reproducible tests, builds, linters, schema checks, runtime checks, or repository inspection. Record failures honestly. Do not call implementation complete merely because files were created.
