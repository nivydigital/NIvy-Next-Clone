# Agent Progress Tracker v2.0

**Purpose:** Per-agent quality gate and progress control system for `nivyindia/Nivy-Next-AIOS`.

**Canonical agent source:** `agents/registry.yaml`  
**Mandatory build standard:** `docs/AGENT-COMPLETENESS-STANDARD.md`  
**Mandatory reusable build procedure:** `docs/agent-implementation-plan/AGENT-BUILD-MASTER-PROMPT.md`  
**Schema:** `schemas/agent-spec.schema.yaml`

## HARD SEQUENCING RULE

> **ONE AGENT AT A TIME.** The next agent **MUST NOT enter implementation** until the current agent has passed every applicable gate G0–G20, has evidence recorded, and is marked `COMPLETE`.
>
> A registry declaration, YAML binding, prompt registration, or passing shared-contract test **does not equal agent completion**.
>
> Any failed, missing, ambiguous, unverified, or unevidenced gate = `BLOCKED` / `NOT_COMPLETE`.

## Status lifecycle

`NOT_STARTED → DISCOVERY → AUDIT → SPECIFICATION → IMPLEMENTATION → TESTING → INTEGRATION → VERIFICATION → EVALUATION → COMPLETE → ACTIVE`

`BLOCKED` can occur at any stage.

### Checkbox rules

- `☐` = not yet proven
- `◐` = work in progress / partial evidence
- `☑` = passed with evidence
- `✗` = failed
- `N/A` = genuinely not applicable **and must include a reason in evidence**
- Never mark `☑` from documentation alone when runtime evidence is required.
- Never use `N/A` merely because implementation is difficult.

## Gate definitions

### G0 — Inventory / identity
Agent ID/name/version match canonical registry; no duplicate or legacy ambiguity.

### G1 — Reuse discovery
Raw-Repository + existing library + internet/authoritative sources searched; reuse/adapt/reject record includes provenance, license and version.

### G2 — Objective / scope
Purpose, responsibilities, non-goals, boundaries and escalation criteria are defined and testable.

### G3 — Input contract
Required/optional inputs, schema, validation, missing/invalid input behavior and source of truth are defined.

### G4 — Skill contracts
Every skill has objective, inputs, procedure, outputs, quality checks, failure/evidence policy and dependencies; bindings resolve.

### G5 — Executable prompt
Bound prompt exists, is executable and contextualized; output format is defined; prompt is injection-resistant and tested.

### G6 — Knowledge / retrieval
Knowledge packs/sources, retrieval rules, freshness/citation requirements and fallback behavior are defined.

### G7 — Memory policy
What is remembered, retention/scope, read/write rules, privacy/security and reset behavior are defined.

### G8 — Model policy
Model/provider, parameters, deterministic requirements, fallback, cost/latency limits and local/open-source preference are defined.

### G9 — Tools / permissions
Least privilege; every tool declared/bound; unknown tools denied; protected side effects approval-gated; secrets protected.

### G10 — Workflow / state
States/transitions, orchestration, retries, timeouts, idempotency, concurrency, compensation and handoffs are defined.

### G11 — Guardrails
Safety/business rules, forbidden actions, approval/escalation, data handling and fail-closed behavior are implemented.

### G12 — Execution
Actual runtime entrypoint/code/workflow exists; dependencies and configuration are documented and reproducible.

### G13 — Postconditions
Agent verifies that intended work actually happened; evidence criteria and failure/rollback path are defined.

### G14 — Output contract
Structured output schema, required fields, quality thresholds, uncertainty/escalation and consumer contract are defined.

### G15 — Audit / observability
Run/tool/request IDs, logs, audit events, metrics, errors, traces and sensitive-data redaction are implemented.

### G16 — Tests
Contract + happy path + negative + output/schema + policy + failure/retry + regression/golden tests pass.

### G17 — Evaluation
Metrics, thresholds, evaluation dataset/cases, evidence and pass/fail decision are recorded.

### G18 — Lifecycle / provenance
Owner, lifecycle, version, provenance, dependencies, license, compatibility and change history are recorded.

### G19 — Integration proof
Required integrations (n8n/Odoo/Qdrant/etc.) work in the supported runtime; live evidence is recorded where applicable.

### G20 — Completion gate
All applicable G0–G19 pass; evidence paths/commit refs are recorded; tracker is updated; only then is the agent eligible for the next agent.

## Blocking rule

If an agent fails a gate:

- mark the specific gate `✗`;
- set the agent status to `BLOCKED`;
- write the exact blocker and required evidence in the final column;
- fix **that agent** before beginning the next agent;
- rerun all affected regression tests after shared components change;
- do not bypass a gate by marking it `N/A`.

## Shared-component regression rule

If a shared prompt, skill contract, registry, runtime, policy, schema, knowledge pack, tool adapter, or workflow engine changes:

1. identify every completed agent affected;
2. rerun its regression/golden tests;
3. restore `☑` only after affected evidence passes;
4. if regression fails, the affected agent becomes `BLOCKED` and the sequence stops.
