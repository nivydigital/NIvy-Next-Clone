# P0.4 — Standard agent run path

**Date:** 2026-09-17

## Target lifecycle (from AGENT-COMPLETENESS-STANDARD)

```
Receive → Validate → Authorize → Plan → Execute → Verify → Commit/Report → Audit
```

## Current implementation

### Generic path
`POST /api/v1/runtime/agents/{agent_id}/run`
- Body: `{ prompt?, prompt_id?, context }`
- Calls `runtime_engine.run_llm(agent_id, prompt, prompt_id, context)`
- Authorization: RuntimeDenied → 403
- **Does not** load agent input schema or call `run_a0XX_*` structured entrypoints

### Dedicated path (A001–A005 only)
`POST /api/v1/runtime/agents/A00X/...`
- Pydantic request models
- Calls `run_a00X_*` which validates required fields, invokes LLM, validates output fields
- Returns `RunResult.__dict__`

### Tool path
`POST /api/v1/runtime/agents/{agent_id}/tools/{tool_id}/execute`
- Approval-aware via `approval_id`
- Email send requires approval (`/api/v1/email/send`)

## Target unified path (to implement)

```
POST /api/v1/runtime/agents/{agent_id}/execute
  1. Load agent from agents/registry.yaml (fail closed if missing)
  2. Validate input against agents/{id}/input.schema.json
  3. Authorize tools/skills from registry permissions
  4. Resolve prompt body (prompt_id) — fail closed if missing when required
  5. Dispatch to backend.app.runtime.a0XX:run_a0XX_* if present
     else fall back to run_llm with declared prompt_id
  6. Validate output against output.schema.json
  7. Append audit event (run_id, agent_id, timings, status)
  8. Return structured result
```

## Idempotency & correlation

- Accept optional `request_id` / `correlation_id` on all execute calls
- Persist audit in runtime_engine.audit list (later: Postgres)
